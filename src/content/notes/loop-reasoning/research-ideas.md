## 研究问题与框架目标

<span id="source-block-e4bb1607-9a13-4496-bd2e-b5ef510694da"></span>

这些研究设想来自一个尚未解决的差距：模型能写出解题过程，并不等于它已经会在不写出过程时完成同样的计算。要研究怎样跨过这个差距，框架必须让我们分别改变初始化、状态更新、监督目标和生成方式，而不是把它们锁在一种配方里。下面先说明每个选择想解决什么问题，再把问题落实为接口能力。已有实验与配方不作为当前架构的前提，具体模型和训练方法继续开放。

<span id="source-block-e43b06e7-0bec-4242-ac0d-563c15b72b87"></span>

## 原始设想与待检验分支

<span id="source-block-d53dc3e2-5f38-4e3b-89a8-b468d1e515fb"></span>

### 显式能力怎样进入内部计算

<span id="source-block-87d911da-36cd-4e55-a0eb-d75d37257696"></span>

一条候选路径是先让裸 Base 学会 Full-CoT，再用自蒸馏教学生通过内部循环利用这些能力。这里立即产生一个需要对照的问题：学生应从原 Base 开始，还是从已经学会 CoT 的检查点继续？两种起点带来的已有能力不同，后续收益也就不能只归给循环方法。框架需要分别表达和比较这两种初始化，让“教师提供了什么”和“学生原来会什么”能够单独分析。

<span id="source-block-ec7017f7-1120-4eb9-8f33-7f6b2ced56e8"></span>

下一步不是只检查学生答案是否更准，而是追问它学会了哪种计算。学生可能能模仿教师文字，却不能把中间结果继续使用；隐状态接近教师，也不能单独说明这些状态在后续操作中起了作用。因此，答案准确、能写过程、隐状态接近教师和能实际续算，需要分别判断。输出监督、内部状态监督和实际续算教学都保留为候选，让监督信号对应我们真正希望形成的能力。

<span id="source-block-a0b5f269-d628-464e-8da5-22aedb712a4f"></span>

### 参数和计算接口可以改变

<span id="source-block-c12c5ed1-3278-4693-a155-e1fc04ca6b39"></span>

一旦学生不能有效续算，就要区分困难来自哪里：现有表示是否适合再次输入、接口是否能完成所需变换，还是骨干本身也需要适应。不同解释对应不同的可训练范围，所以骨干、门控和计算接口中的参数都可以纳入训练。是否冻结骨干、使用小 LoRA、固定四轮或回填最后一层，应由具体问题和相应对照决定。普通 Base 上的循环增强仍是近期主线，原生循环模型提供参考。

<span id="source-block-aded3f88-65e5-4dc5-8467-f0583fd624f3"></span>

### 能力变化与 OPD 恢复

<span id="source-block-bbb3f525-ce46-43eb-a813-da633f6c38a5"></span>

把训练集中到内部计算后，还需要观察显式 CoT 能力怎样变化。若它下降，可以研究后续恢复；若希望持续保留，也可以在训练过程中兼顾。由此形成两条可比较的路径：持续保持能力，以及先专门化、再恢复能力。OPD 可作为形成新能力或恢复文字行为的候选方法，但不预设它一定有效，也无须为了验证恢复而主动制造能力损伤。

<span id="source-block-3b96fef4-8890-4a6d-9f79-45df2a8e1aff"></span>

恢复实验应同时保留三个问题。CoT 恢复幅度说明文字行为找回了多少；内部收益的保留说明恢复是否妨碍了先前形成的循环计算；恢复成本决定整条训练路径是否值得。若只报告旧 CoT 能力恢复，却不检查内部循环的收益，就仍未回答最初的研究问题。

<span id="source-block-95f35426-25cb-4fdc-aa71-3e9617f4dbf5"></span>

### 少量文字记录与成本权衡

<span id="source-block-92bbf747-c0e4-4d3b-8b4b-11ec8cbb2cca"></span>

内部循环也不必排斥少量文字。某些关键中间结果是否适合写成短记录，再由后续内部计算继续使用，同样值得检验。这样，比较对象不只是“写或不写 CoT”，还包括写多长、内部算多深，以及两者怎样配合。长期目标是在公平的训练和推理预算下，相对合理调优的短 CoT、完整 CoT 获得更好的能力与成本组合。框架因此分别记录文字位置推进、内部深度和实际执行成本。

<span id="source-block-8fdf15c5-fcbc-482e-80ce-97fd74035ef0"></span>

### 门控如何超越固定深度

<span id="source-block-a03fbdf7-5466-403d-aee2-d26e76c7ff20"></span>

既然可以选择文字长度或内部深度，就会产生门控问题：面对当前这道题，模型应该选哪个计算方案？先固定同一检查点、评测协议、候选执行策略和成本口径，避免把模型差异混入选择能力。候选可以是内部深度、文字长度或两者的组合。令 Uₖ 表示候选 k 的净效用，𝓗 表示选择当时可见信息所生成的 σ 代数；以下假定候选有限、效用可积，成本系数 λ 的单位与实际成本 C 一致。

<span id="source-block-60e6a3aa-f164-4bee-b09b-9ceb83912306"></span>

```math
U_k=R_k-\lambda C_k.
```

<span id="source-block-12c51083-60aa-41a4-b7bf-ddcbfe74f402"></span>

可部署的选择器只能根据做决定时已经看见的信息选出候选 Kπ。它不能先知道正确答案，也不能先运行所有候选、看过未来奖励后再把这种事后挑选计为门控的表现。在数学上，这正是要求 Kπ 对 𝓗 可测。对这些选择器，有限候选下有：

<span id="source-block-bdb1842f-8dd1-4270-b2e4-d08169987cd1"></span>

```math
\max_k\mathbb E[U_k]
\le
\sup_{K_\pi\ {\cal H}\text{-measurable}}
\mathbb E[U_{K_\pi}]
=
\mathbb E\left[\max_k\mathbb E[U_k\mid{\cal H}]\right]
\le
\mathbb E\left[\max_k U_k\right].
```

<span id="source-block-467db1de-a74b-4057-9a8c-61ac57331e69"></span>

左端把所有题都交给同一个最佳固定候选，它本身也是一种合法选择器，所以不会优于中间的最优选择。中间的等号描述理想上限：给定当前信息，最好的决策是选条件期望效用最高的候选。最右端则先看全部候选的实际结果，再逐题挑最好者；条件 Jensen 不等式给出这个事后 oracle 上界。因此，逐题挑选最优深度能显示改进空间，却不能证明 gate 已会部署时的选择。训练中的 loss-improvement 标签也要由当时可见状态预测，部署时不会直接获得未来标签。

<span id="source-block-4eb1c718-b135-45f5-ba50-6d5ac6f6a4d1"></span>

若候选生成含有随机性，还要说明不同候选的潜在结果如何共同构造，即它们的随机量怎样耦合；事后最大值会受这一设定影响。若成本 C 用实测延迟表示，则固定硬件、批调度和计时边界，不能直接用平均循环轮数替代。开发集用于调阈值和选择 λ，评测集用于最终比较；对照中保留最佳固定候选、简单合法选择器和完整成本曲线。

<span id="source-block-8cb43665-4c1f-4ebf-8c0d-0aa31fb93278"></span>

这给出一条清楚的研究顺序：先确认额外计算在什么情形下带来收益，再检查当前可见特征能否预测这种收益，最后检验学习到的选择能否改善完整任务收益与实际成本。只做到第一步，还不能宣布门控成功。联合动作的定义见[强化学习页](/notes/loop-reasoning/reinforcement-learning/)，成本测量见[分布式与性能页](/notes/loop-reasoning/systems-evaluation/)。

<span id="source-block-816fd285-1f9d-4323-a705-6ed8361277ff"></span>

### 表征动力学与尺度

<span id="source-block-ba1a6f2b-1276-48a2-9958-8816ba42cc36"></span>

无论选择多少轮，上一轮产生的表示都要成为后续计算能利用的状态。这自然引出动力学问题：反复送回模型后，尺度怎样累积、各轮状态怎样相关、每次更新改变了多少，以及后续层是否真正使用了这些变化。因而范数、相关性和更新强度都值得观察，但单个向量的范数不能代表完整计算状态；必要的缓存、位置和路径信息也必须纳入描述。

<span id="source-block-0d228a2e-3ad7-4f80-bbc2-ef2af42cf10a"></span>

理论在这里的作用，是把这些观察组织成宏观量和可检验预测。DMFT 等工具可以帮助提出这样的预测，目前却还不能直接提供经过验证的接口设计规则。我们可以先做尺度和梯度诊断，再用结果判断哪些理论工具值得深入；性能尚未改善，不妨碍开展这些诊断，也无须先完成一整套理论课程。

<span id="source-block-783df14d-aa92-4e6a-b4e6-0d05f19c78ab"></span>

### 组合与可复用中间状态

<span id="source-block-cbcb4cf6-0ee7-4cb3-9f3b-2b80ff5dda21"></span>

最终还要追问：内部状态保存的是可重复利用的中间结果，还是只对当前答案有帮助的某种表示？让同一中间结果服务于多种后续操作，才能更具体地检查模型怎样使用已有知识。Q2 从组合与重用切入，Q3 关注信息保存和历史 K/V，分别帮助提出续算和记忆的问题；具体机制仍需证据，不能因把两个方向联系起来，就视为已经成立。

## 框架能力要求

<span id="source-block-7e62256e-48c7-4bc4-9457-304cd4a283fd"></span>

| 研究设想 | 框架需要逐步支持的能力 |
| - | - |
| 不同学生初始化与参数更新范围 | 明确的模型加载、组件加载与参数组配置 |
| 自蒸馏与过程教学 | 教师所见输入、返回目标及监督位置的接口 |
| 接口与门控训练 | 独立可检查的状态更新、路由和梯度路径 |
| 自主计算与 OPD | 文字轨迹来源、内部深度决策与模型版本分别记录 |
| 少量文字配合内部循环 | 文字位置、循环深度、缓存更新与停止规则分别定义 |
| 表征动力学与尺度 | 按需采集状态范数、相关性、更新幅度与梯度，控制诊断开销 |
| 中间结果重用与历史 K/V | 明确的状态所有权、注意力可见性和缓存生命周期 |

## 如何记录新的研究判断

<span id="source-block-19789be3-8409-436e-9f45-57b880bb46f2"></span>

每次只记录能改变判断的增量：

<span id="source-block-cfaeb578-0dfb-4787-b86c-cae43fee0e37"></span>

- **观察**：观察到了什么。

<span id="source-block-3970919c-0284-4f5d-bb63-ea75815ab574"></span>

- **依据**：依据哪个代码版本、配置或结果。

<span id="source-block-3a4ba0b2-9c48-42b3-9685-d489442e292f"></span>

- **竞争解释**：有哪些竞争解释。

<span id="source-block-f37d4522-6993-4c07-aea4-c38bd9dc6105"></span>

- **反证**：哪项证据会削弱当前解释。

<span id="source-block-f2241821-ba4d-4acd-9af1-f8d4a97995fe"></span>

- **下一步**：需要阅读、只读核查还是新的实验设计。

<span id="source-block-706e6e81-36b6-41a3-9c98-56e9ef6e0383"></span>

记录时区分实际观察、对观察的解释和尚未运行的方案。任务是否完成，以实际执行回执判断。

<span id="source-block-9d0010a0-45fd-4c04-8133-0916c19af1d7"></span>

现有完整设想与实验卡保留在 [原研究任务书](https://chatgpt.com/library?file_id=libfile_746d702f0c708191bdd446def025e898&account_id=personal)。这里维护当前讨论重点，不复制所有历史计划。

<span id="source-block-0a007333-4882-4c22-b47e-1be916a161c1"></span>

```text
请先读取本页和研究入口，围绕我提出的想法分析框架需要支持哪些计算。明确模型执行、状态与缓存、目标和教师信号、训练与生成的边界，结合实际源码解释接口取舍。保留不同初始化、监督与循环形式的选择，不把历史实验配方作为前提，也不默认 OPD 能恢复能力。当前以结构建设和源码理解为主。
```
